# スライド文章検査

対象デッキのMarkdownソースを `docs/writing-guide.md` のルールに照らして検査する。見た目の検査は `slide-layout-check`（別スキル）。

## 手順

### 1. 機械的検出（パターンマッチ）

対象の `.md` をReadし、以下を検出する：

| 検出対象 | 判定方法 |
|---|---|
| 3項目箇条書き | 連続する `-`/`*` 項目がちょうど3つのブロック（サブ項目は親に合算しない） |
| 機械的接続詞 | 「まず」「次に」「最後に」「はじめに〜次に〜」の順序表現 |
| 定型の抽象表現 | 「〜が重要です」「〜が求められる」「〜していきましょう」など、固有名詞・数字を伴わない主張 |

HTMLコメント（発表者ノート）と frontmatter は検査対象外。

### 2. 構造検査（読解）

パターンマッチでは取れない「予定調和」を読んで判定する：

- **同一構造の連続** — 「見出し＋箇条書き」だけのスライドが3枚以上続いていないか
- **等分な説明** — 全項目が同じ行数・同じ粒度で、主張の濃淡がないスライド
- **1スライド複数メッセージ** — 見出しと本文が別の主張をしているスライド
- **具体例の欠如** — 抽象論だけで、固有名詞・数字・実体験がないスライド

### 3. 報告と修正

「スライド番号（見出し） / 検出ルール / 修正案」の一覧で報告する。

修正の適用ルール：

- 接続詞の削除、3項目→2または4項目への構成変更などの**機械的修正は適用してよい**
- **「自分だけが語れる具体例」を捏造しない**。具体例が欠けている箇所は `<!-- TODO: ここに自分の体験・事例を入れる（例: どんな場面で/何が起きた/どうした） -->` のプレースホルダを置き、ユーザーに委ねる
