# スライドレイアウト検証

対象のMarpスライドを1ページずつ画像化し、目視相当のチェックで崩れを検出して修正するループ。

## 前提

- リポジトリルートで実行する（`.marprc.yml` がエンジン・テーマ・`allowLocalFiles` を解決する）
- 判断基準は `docs/style-guide.md`、修正の引き出しは `template/patterns.md`

## 手順

### 1. 全スライドをPNG化

```bash
pnpm exec marp <対象.md> --images png -o <scratchpad>/layout-check/deck.png
```

`deck.001.png`, `deck.002.png`, ... が生成される（`<scratchpad>` はセッションのscratchpadディレクトリ）。

### 2. 各PNGをReadして検査

1枚ずつ画像を読み、以下を確認する:

| 検出項目 | 判定 |
|---|---|
| オーバーフロー | テキスト・図が下端/右端で切れている |
| 過密 | 1カラムに箇条書き5項目以上、または余白がほぼない |
| 色の乱用 | アクセントカラーが3色以上使われている |
| 文字の縮小乱用 | 本文が明らかに小さい（脚注以外での `.text-xs` 以下） |
| 画像との衝突 | 背景画像とテキストが重なって読めない |
| 空きすぎ | 内容が上部1/3に偏り下が空洞 |

### 3. パターン別の修正を適用

| 症状 | 修正 |
|---|---|
| 下部が切れる | 項目を削る → それでも駄目なら `:::c` で2カラム化（patterns.md P09） |
| 5項目以上 | `:::c` 2カラム化、または2スライドに分割 |
| 色が多い | 意味の薄い色指定を外し、1〜2色に絞る |
| 画像と文字の衝突 | `![bg right:NN% fit]` の幅を調整、または `opacity:.15` に下げる |
| 空きすぎ | `![bg right]` で画像を足す、または前後スライドと統合 |

### 4. 再レンダリングして確認

修正したスライドのみ再度PNG化し、解消を確認する。全スライドがクリーンになるまで2〜4を繰り返す。

### 5. 報告

「スライド番号 / 検出した問題 / 適用した修正」の一覧で報告する。問題ゼロならその旨を明記する。
