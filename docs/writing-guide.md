# 文章ガイド

スライドの「文章」の規範。見た目（色・タイポグラフィ・レイアウト）は `docs/style-guide.md` を参照。
原稿を書くとき・AIが生成した原稿をレビューするときに読む。機械的な検査は `slide-writing-check` スキルが本ガイドを基準に行う。

## 大原則: AIは足す。人間は削る

- 構造化・網羅・叩き台づくりはAIに任せてよい
- **何を省くかの判断と、自分だけが語れる具体例の供給は人間の仕事**。AIはここを代替できない（それらしい体験談を捏造してしまうため、むしろ任せてはいけない）

## 「AIっぽさ」を排除するルール

AIは統計的に頻出するパターンを再現するため、放置すると「予定調和」な原稿が量産される。聴衆の脳は予測を裏切られた瞬間に活性化する — 以下のパターンを機械的に避ける。

| # | ルール | 理由 |
|---|---|---|
| 1 | 箇条書きを3項目で揃えない。**2つか4つ**にする | 「3点セット」はAI生成物の最頻出パターン。5つ以上は分割（style-guide 原則3） |
| 2 | 「まず・次に・最後に」等の機械的接続詞を使わない | 順序は構造（スライドの並び・番号）で示す |
| 3 | 等分な説明をしない | 全項目が同じ行数・同じ粒度なのは、主張の濃淡がない証拠。核心に紙面を偏らせる |
| 4 | 抽象的で当たり障りのない表現を避ける | 「重要です」「〜が求められる」は固有名詞・数字・実体験に置き換える |

## 作成ワークフロー（メッセージ先行）

スライドを作り始める前に、原稿の骨格を固める：

1. 伝えたいメッセージを箇条書きで**5〜7個**書き出す（スライドはまだ作らない）
2. 各メッセージに**「自分だけが語れる具体例」**を付ける。付けられないメッセージは削る候補
3. AIに構成・網羅性のレビューを依頼し、アウトラインを固める
4. `template/patterns.md` からレイアウトを選んでスライド化する
5. `slide-writing-check` で文章を検査し、指摘を修正する
6. `slide-layout-check` で見た目を検査する

## AIにレビューを依頼するときの観点

- 各スライドが1メッセージになっているか
- 具体例のない抽象スライドはどれか
- 削れるスライドはどれか（「網羅した」より「記憶に残った」が成果）
- 同じ構造（見出し＋箇条書き）のスライドが3枚以上続いていないか
